Improvements I would add

More useful in daily use

Popup in the toolbar instead of the options page: on/off switch, button "add current site", and counter of blocked links. It is the change that makes the most difference in daily use.
Exceptions: always-allowed external domains, global or per-site. They are needed for SSO and login (accounts.google.com), CDN, and similar cases, and they also solve the third-party iframe problem.
Badge on the icon with "ON" or the number of blocked clicks in the tab, via chrome.action.setBadgeText. Content scripts cannot call it, so pass through the service worker with a message, as already done for iframes.
Visual marking of external links (dashed border or cursor: not-allowed) with a MutationObserver that follows dynamic links. So you know before clicking. It must be done carefully on very heavy pages.

Security and quality of the alert

5. Highlight the domain in bold in the URL, with a warning for the punycode hostname (xn--, homoglyphs) and for the URL with user@host. It is useful against phishing, and in a phishing email it is the data that counts.
6. "Copy clean URL", which removes utm_*, fbclid, gclid, and similar values, next to the normal "Copy link".
7. Dark theme for the alert with prefers-color-scheme, and a focus trap on the keyboard.

More robust coverage

8. window.open and location.href from JavaScript: resolve with a content script in the "MAIN" world that wraps window.open. Alternatively, a navigation-level control with webNavigation.onBeforeNavigate, which is the hardest to bypass but requires more work to show the URL in the alert.
9. Form with external action: submit listener in capture phase, with the same logic as links.

Management and distribution

10. Import/export of the list in JSON, and chrome.storage.sync to keep it the same across devices.
11. Default list preloaded in chrome.runtime.onInstalled, useful when passing it to friends.
12. Log of the last N blocked links in the options page, with quick copy.
13. Translations (_locales) if friends do not speak English.

On distribution: with the ZIP file, the only realistic route is an "unpacked extension". An .crx outside the store is rejected by Chrome on Windows and macOS, unless there is a corporate policy. A Git repository with git pull and reload makes updates more comfortable.
