How to test

Use more than a normal click. Link Guard is designed to intercept every common way of following a link.

  • Normal click The popup should appear and the page must not navigate.
  • Middle click The popup should appear instead of opening a new tab.
  • Ctrl/Cmd + click The popup should appear instead of opening a new tab.
  • Keyboard Enter Focus a link, press Enter, and the popup should appear.
  • Right click The popup should replace the normal context menu on an external link.
  • Drag and drop Dragging an external link should be stopped and the popup shown.

Close each popup with Cancel or Escape before testing the next link. The popup is modal, so the page behind it is intentionally inactive until it closes. If a link opens normally, the current host is not configured as protected or the extension is not loaded.

Control cases

These links stay on the protected host and should be allowed. They prove that the extension is not blocking every link blindly.

Allowed

Internal relative link

A relative link stays on the same host. It should reload the page without a Link Guard popup.

?control=relative ?control=relative

Expected: the page reloads and shows a control message. No popup.

Allowed

Internal absolute link

This link uses the current origin explicitly. It is still the same host, so it should be allowed.

Internal absolute link set from the current page URL

Expected: the page reloads and shows a control message. No popup.

Basic external links

These are ordinary external destinations. They are blocked because they leave the protected host, even when the destination itself is harmless.

Blocked

Normal external link

The simplest case: a link to another domain. The popup should show the destination and copy actions.

https://example.com/ https://example.com/

Expected: “External link blocked”, destination example.com, no special warning.

Blocked

External link with tracking parameters

The clean-link action should remove known tracking parameters while keeping the real content parameter and fragment.

https://example.com/product?utm_source=email&utm_medium=newsletter&id=42&fbclid=abc#details https://example.com/product?utm_source=email&utm_medium=newsletter&id=42&fbclid=abc#details

Expected: the clean link should be https://example.com/product?id=42#details.

Blocked

Unencrypted HTTP link

The destination is available over plain HTTP. The popup should add the “Unencrypted connection” warning.

http://example.com/ http://example.com/

Expected: external-link popup with the HTTP warning chip.

Blocked

IP address instead of a domain

Users cannot judge an IP address as easily as a domain name. The popup should show the IP warning. This address is in the reserved TEST-NET-1 range, so it is not a real destination.

http://192.0.2.1/ http://192.0.2.1/

Expected: external-link popup with the “IP address” warning chip.

Blocked

Non-standard port

A familiar domain on an unusual port can be a different service. The popup should show the port warning.

https://example.com:8443/ https://example.com:8443/

Expected: external-link popup with the “Non-standard port” warning chip.

Redirect wrappers

Webmail often rewrites links through a redirect service. The extension should unwrap the real destination before deciding whether the link is external.

Blocked

Google/Gmail redirect wrapper

The visible href is on google.com, but the real destination is in the q parameter. The popup should show evil.example, not Google.

Google wrapper to evil.example/login https://www.google.com/url?q=https%3A%2F%2Fevil.example%2Flogin%3Futm_source%3Demail&sa=D&source=gmail

Expected: destination evil.example; clean link https://evil.example/login; original Google wrapper shown separately.

Blocked

Double-encoded Google wrapper

The destination is encoded twice. The extension should decode it repeatedly and still find the real host.

Double-encoded Google wrapper https://www.google.com/url?q=https%253A%252F%252Fevil.example%252Fdouble

Expected: destination evil.example, path /double.

Blocked

Outlook SafeLinks wrapper

Microsoft 365 rewrites links through SafeLinks. The extension should unwrap the url parameter and show the real destination.

Outlook SafeLinks wrapper to evil.example/outlook https://nam12.safelinks.protection.outlook.com/?url=https%3A%2F%2Fevil.example%2Foutlook&data=test

Expected: destination evil.example, path /outlook.

Blocked

Fake Google-like wrapper

A host that merely starts with “google” is not Google. The extension must not trust the q parameter here. The actual destination is google.example, not evil.example.

Lookalike wrapper: google.example https://google.example/url?q=https%3A%2F%2Fevil.example%2Ffake

Expected: destination google.example. The embedded evil.example must not be treated as the destination.

Blocked

Shortened link

The final destination is hidden behind a shortener. The extension should warn that the destination is unresolved and that the clean link may not be final.

https://bit.ly/linkguard-test-does-not-exist https://bit.ly/linkguard-test-does-not-exist

Expected: “Shortened link” and “Destination not resolved” warnings.

Blocked

Google wrapper with no destination

The link uses the Google redirect path but has no usable destination parameter. It should be blocked as unresolved rather than being treated as an internal Google link.

https://www.google.com/url?sa=D https://www.google.com/url?sa=D

Expected: “Destination not resolved” warning.

Similar-looking domains

These are the main phishing cases. Compare each fake domain with the real one. All external links are blocked, but the fake domains add a Unicode or lookalike warning.

Blocked

Cyrillic homograph: pаypal

The second character in pаypal is Cyrillic а (U+0430), not the Latin a (U+0061). They look identical in many fonts. The popup should show a red Unicode warning, the Unicode form, the punycode form, and the Latin lookalike.

Lookalike

Fake domain

https://pаypal.example/login Unicode: https://pаypal.example/login Punycode: https://xn--pypal-4ve.example/login Skeleton: paypal.example
Real domain

Legitimate PayPal

https://paypal.com/login https://paypal.com/login

Expected: red “Warning: confusable Unicode characters” warning on the fake domain; no Unicode warning on the real domain.

Blocked

Same fake PayPal domain in punycode

Browsers store the fake domain as punycode. This is the same destination as the previous case, written in the form the browser uses internally.

https://xn--pypal-4ve.example/login https://xn--pypal-4ve.example/login

Expected: the same Unicode homograph warning, with Unicode pаypal.example and punycode xn--pypal-4ve.example.

Blocked

Greek homograph: gοοgle

The two “o” characters in gοοgle are Greek omicron (U+03BF), not Latin o. The destination looks like Google but is not Google.

Lookalike

Fake domain

https://gοοgle.example/ Unicode: https://gοοgle.example/ Punycode: https://xn--ggle-0nda.example/ Skeleton: google.example
Real domain

Legitimate Google

https://google.com/ https://google.com/

Expected: red Unicode warning, scripts Latin and Greek, lookalike google.example.

Blocked

ASCII lookalike: paypa1

The digit 1 replaces the letter l. This is not a Unicode homograph, so Link Guard will not add a special warning. The destination text in the popup is the defense.

Lookalike

Fake domain

https://paypa1.example/ https://paypa1.example/
Real domain

Legitimate PayPal

https://paypal.com/ https://paypal.com/

Expected: external-link popup with destination paypa1.example; no Unicode warning.

Blocked

Subdomain deception

The real destination is the rightmost part of the host. Here the host is a subdomain of evil.example; paypal.com is only part of the subdomain name.

Lookalike

Fake domain

paypal.com.evil.example/login https://paypal.com.evil.example/login
Real domain

Legitimate PayPal

https://paypal.com/login https://paypal.com/login

Expected: destination paypal.com.evil.example; the real registrable domain is evil.example.

Blocked

Userinfo deception

Everything before the @ is a username, not the host. The browser actually navigates to evil.example. The popup should show the real destination and the “Credentials in URL” signal.

https://paypal.com@evil.example/login https://paypal.com@evil.example/login

Expected: destination evil.example, plus the userinfo warning. Do not read “paypal.com” as the host.

Blocked

Same name, different TLD

The name matches, but the top-level domain is different. Link Guard blocks it as external and does not add a special warning, so the destination line is important.

Lookalike

Fake domain

https://paypal.example/ https://paypal.example/
Real domain

Legitimate PayPal

https://paypal.com/ https://paypal.com/

Expected: destination paypal.example; no Unicode warning.

Blocked

Legitimate internationalized domain

Not every non-ASCII domain is an attack. This legitimate IDN should get a yellow informational note, not the red homograph warning.

Internationalized

Unicode form

https://münchen.de/ https://münchen.de/
Internationalized

Punycode form

https://xn--mnchen-3ya.de/ https://xn--mnchen-3ya.de/

Expected: yellow “Internationalized domain” note with Unicode and punycode; no red homograph warning.

Suspicious URL forms

These are external links that should also show additional warning chips in the popup.

Blocked

Many subdomains

A long chain of subdomains can push the real domain out of view. The popup should show the “Many subdomains” warning.

https://www.paypal.com.security-check.example/login https://www.paypal.com.security-check.example/login

Expected: external-link popup with the many-subdomains warning.

Blocked

Encoded characters in the host

Percent-encoded host characters should be normalized before the destination is shown. This fake PayPal host uses a percent-encoded Cyrillic character.

https://p%D0%B0ypal.example/encoded https://p%D0%B0ypal.example/encoded

Expected: the popup shows the decoded Unicode host and the homograph warning.

Link text deception

The visible text can say one thing while the actual link points somewhere else. The popup should compare the text with the destination.

Blocked

Text says PayPal, href goes to evil.example

The link text contains a different domain from the actual destination. The popup should show the “Link text differs from destination” warning.

https://paypal.com/login Visible text: https://paypal.com/login Actual href: https://evil.example/login

Expected: destination evil.example and the text-mismatch warning.

Unsafe protocols

These are not normal web destinations. Link Guard should block them and explain that the protocol is unsafe.

Blocked

javascript: link

A javascript: URL runs code in the page instead of navigating to a website. It should never be opened from the popup.

javascript:alert('Link Guard test') javascript:alert('Link Guard test')

Expected: “Unsafe protocol” warning; no navigation.

Blocked

data: link

A data: URL embeds its own content. It can be used to show a fake page without a normal domain.

data:text/html,%3Ch1%3ELinkGuard%20test%3C%2Fh1%3E data:text/html,%3Ch1%3ELinkGuard%20test%3C%2Fh1%3E

Expected: “Unsafe protocol” warning; no navigation.

Forms

Forms are blocked by the same protection. An external action should open the “Form submission blocked” popup instead of sending data.

Blocked

Form with an external action

This form would post the email address to evil.example. The popup should identify it as a form and show the action URL.

Action: https://evil.example/collect Method: POST

Expected: “Form submission blocked”, action https://evil.example/collect, and a note that the form was not sent.

Reminder: the fake destinations use the reserved .example domain wherever possible, so accidental navigation cannot reach a real phishing site. The real paypal.com, google.com, and münchen.de links are included only for comparison and are still blocked because they are external.
